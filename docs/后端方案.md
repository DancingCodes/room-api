# Room 后端方案

## 目标

主流程：

```txt
邮箱验证码登录 -> 新邮箱自动创建用户 -> 房间列表 -> 创建或进入房间 -> 房间详情
```

## 第一版后端提供

- 邮箱验证码发送
- 邮箱验证码登录
- 新邮箱首次登录自动创建用户
- 自动生成昵称和头像
- 当前用户资料
- 用户头像更新
- 房间创建、列表、详情、进入、离开
- 房主自动转让
- 文字消息
- WebSocket 房间事件广播
- 开麦/闭麦状态同步

数据库表结构使用 SQL migration 管理。当前初始化脚本为 `migrations/001_init_schema.sql`。服务启动时只连接 MySQL，不自动创建、不修改、不执行 migration。

## users 表

```sql
CREATE TABLE users (
  id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  email VARCHAR(128) NOT NULL,
  nickname VARCHAR(8) NOT NULL,
  avatar_url VARCHAR(512) NOT NULL,
  created_at DATETIME NOT NULL,
  updated_at DATETIME NOT NULL,
  UNIQUE KEY uk_users_email (email),
  UNIQUE KEY uk_users_nickname (nickname)
);
```

## 认证规则

- `POST /api/v1/auth/email-code` 发送验证码，请求体只包含 `email`。
- `POST /api/v1/auth/email-login` 校验验证码，请求体包含 `email` 和 `email_code`。
- 如果 `email-login` 的邮箱不存在，后端自动创建用户，然后直接返回 `token + user`。
- 自动昵称来自邮箱 `@` 前面的部分，最多 8 个 Unicode 字符；如果昵称重复，自动追加数字后缀。
- 自动头像 URL 使用邮箱作为稳定 seed 生成；用户后续可先通过 `/api/v1/uploads/image` 上传头像拿到 URL，再通过 `PATCH /api/v1/users/me` 保存 `nickname` 和 `avatar_url`。
- 用户不再有账号和密码字段。
- JWT 有效期 100 日历年。
- `current_room_id` 不在 `users` 表存储，接口返回时从 `room_members` 查询。

## 验证码规则

- 验证码为 6 位数字。
- 验证码 5 分钟有效。
- 同一邮箱同一用途 60 秒内只能发送一次。
- 同一邮箱同一用途 1 小时最多发送 5 次。
- 发送新验证码时，同一邮箱同一用途的旧验证码失效。
- 校验验证码时，只接受未使用、未过期的最新一条同用途验证码。
- 验证码邮件使用腾讯云 SES API 发送，`TemplateData` 传 `{"code":"123456"}`。

## 房间、消息、WebSocket

- 一个用户同一时间只能在一个房间；重复进入当前已经所在的同一房间时视为成功。
- 房间名称为 `用户昵称 + 的房间`。
- 房主只以 `rooms.owner_id` 为准，成员 `is_owner` 由接口计算。
- WebSocket 使用 `Authorization: Bearer jwt_token` 请求头鉴权。
- WebSocket 断开等于离开房间。
- HTTP 发送消息后广播 `message.created`。
- 房主离开后自动转让；最后一个成员离开后删除房间和消息。
